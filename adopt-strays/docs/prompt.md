# PROJECT: LITTLE ENCOUNTERS
## 小小相遇所｜台灣動物認養圖鑑
### A tiny world of real animals waiting to meet someone.

你是一位同時具備以下能力的創作者：

- Creative Front-end Developer
- Art Director
- Interaction Designer
- SVG Illustrator
- Motion Designer
- Narrative Designer
- Game Experience Designer
- Data Engineer
- Accessibility Engineer

請直接開發一個完整、可執行的互動網站。

這不是普通的動物認養搜尋平台。

**這是一個以真實台灣收容動物資料驅動、具有轉蛋系統、動物圖鑑、故事性與角色互動的沉浸式小世界。**

我希望人們因為畫面可愛而進來，因為相遇的驚喜而留下，因為認識某一隻真正存在的動物，而萌生進一步了解與認養的意願。

核心理念：

**每一顆轉蛋裡，不是一個虛構角色，而是一隻真正在台灣等待被認識的動物。**

這個作品的最終目的不是讓使用者抽更多轉蛋，而是增加真實收容動物的曝光、關注與負責任的認養機會。

請以完整作品為目標，不要只做概念 Demo。

# 01｜美術方向：極簡可愛絹印世界

這是最重要的要求之一。

## 1.1 參考我的既有作品

請先檢查目前工作環境是否可以取得我的：

- 絹印網站（可能位於 `/tools/retro-printer`）
- 集章網站（可能位於 `/tools/stamp-tour`）
- Laundry Weather 美術參考圖

以上路徑請實際確認。

如果可以取得，請仔細研究它們的：

- 圖像比例
- 幾何造型
- 色塊配置
- 插畫簡化程度
- 印刷錯位感
- 配色與彩度層次
- 可愛但不幼稚的視覺語言

如果無法存取，不得假裝已經研究過。

## 1.2 美術關鍵字

- Minimal Geometric Illustration
- Japanese Editorial Illustration
- Cute Flat Shapes
- Bold Color Blocking
- Silkscreen
- Risograph
- Paper Cutout Animation
- Playful Graphic Design
- Whimsical Tiny World
- Illustrated Interactive Storybook

視覺必須具有鮮明的藝術指導。

不要做成：

- 普通寵物商城
- 電商商品列表
- 動物醫院 App
- 常見認養網站模板
- 大量圓角卡片的 SaaS 介面
- 過度複雜的遊戲介面
- 3D 擬真轉蛋機
- 粉紅色系的廉價可愛風
- 全畫面都使用高彩度配色

**美術必須先是一幅漂亮的平面作品，再加入互動。**

## 1.3 色彩策略

請建立具有不同明度、彩度與色相的有限色盤。

例如：

- 米白
- 鼠尾草綠
- 陶土紅
- 芥末黃
- 灰紫
- 深墨綠

但不要被這組配色限制。

可以自由嘗試其他具有個性的配色。

重要原則：

- 大面積背景不必使用高彩度。
- 重要角色與互動物件可以有鮮明重點色。
- 適度利用紙張底色。
- 色塊本身必須具有造型美感。
- 質感不能取代構圖。
- 絹印錯位與網點應少量使用。

## 1.4 插圖語言

動物、家具、轉蛋機、招牌與場景都應具有：

- 簡單的幾何輪廓
- 少量但準確的細節
- 可愛的比例
- 充分的留白
- 清楚的視覺焦點

請避免使用普通 Emoji 作為主要插圖素材。

# 02｜世界觀：一間小小的相遇所

網站是一個虛構的、溫暖的小地方。

這裡不是實際的動物收容所。

它更像：

**一間專門讓人與台灣各地收容動物相遇的奇妙小店。**

裡面可以有：

- 轉蛋機
- 動物圖鑑書架
- 一張小櫃檯
- 可愛的站務員
- 今日相遇公告板
- 收藏相遇紀錄的小冊子

但不要在畫面裡塞入太多東西。

請用少量且精緻的物件建立世界感。

## 2.1 NPC 站務員

希望有一位原創的主要 NPC。

可以是：

- 小小的店員
- 幾何動物角色
- 奇怪的小生物
- 有點呆呆的管理員

不要沿用其他作品的既有 NPC 設定，除非能確認授權與角色設定。

這位站務員的性格：

- 認真
- 有點天然呆
- 溫柔
- 偶爾荒謬幽默
- 很喜歡介紹動物
- 不會強迫使用者認養

例如：

「歡迎光臨！今天也有好多朋友想認識你。」

「咦？這位朋友的耳朵好有特色。」

「你可以先認識牠，不用急著做決定。」

「找到喜歡的朋友了嗎？要不要看看牠住在哪裡？」

站務員應該是世界的一部分，而不是一直跳出來的教學視窗。

# 03｜首頁：相遇所大廳

第一個畫面應具有強烈的沉浸感。

不是普通 Landing Page。

我希望使用者像走進一本會動的絹印故事書。

## 3.1 主視覺

一個全螢幕的可愛平面場景。

包含：

- 一台精緻的轉蛋機
- 一位小小 NPC
- 少量家具或植物
- 一本動物圖鑑
- 一些具有辨識度的小物件

不要過度裝飾。

每個物件都應有明確的構圖目的。

## 3.2 首頁主要互動

最重要的操作：

**「今天會遇見誰？」**

按下後開始轉蛋。

另外可以有：

- 翻閱圖鑑
- 查看收藏的相遇
- 依地區尋找動物
- 關於本站

介面應該非常精簡。

## 3.3 待機動畫

使用者不操作時：

- NPC 偶爾眨眼。
- 機器有微小的待機動作。
- 某個小物件輕輕晃動。
- NPC 偶爾冒出一句短台詞。

整體像一座安靜、可長時間欣賞的小小舞台。

不要大量播放重複動畫。

# 04｜核心功能：轉蛋相遇系統

這是整個網站最重要的互動。

轉蛋裡裝的是一張「認識真實動物」的相遇卡，而不是動物本身。

請建立一套完整、流暢、有驚喜感的轉蛋流程。

## 4.1 轉蛋流程

1. 使用者按下「今天會遇見誰？」
2. 轉蛋機開始轉動。
3. 轉蛋掉落。
4. 轉蛋打開。
5. 出現動物的相遇卡。
6. 可以查看完整介紹。
7. 可以收藏、分享或繼續相遇。

整個過程應有精緻的動畫節奏。

不是按一下，立即彈出普通 Modal。

## 4.2 動畫設計

轉蛋動畫可以包含：

- 旋鈕轉動
- 機器輕微晃動
- 膠囊滾落
- 膠囊彈跳
- 膠囊打開
- 相遇卡出現

請使用 SVG 與輕量動畫技術。

優先追求可愛、幽默和節奏感。

不要追求擬真物理。

## 4.3 動畫時間

完整轉蛋動畫建議約 3～5 秒。

這只是初始參考，可依實際體驗調整。

必須允許：

- 跳過動畫
- Reduced Motion
- 鍵盤操作
- 動畫結束後正確移動焦點

不要強迫使用者每次都看完整演出。

## 4.4 轉蛋抽選規則

使用真實可認養動物資料。

基本規則：

- 只納入符合目前可展示條件的動物。
- 不應抽到資料已確認失效的動物。
- 避免同一場瀏覽期間連續重複。
- 不要只推薦外表最可愛的動物。
- 沒有照片的動物也應有合理的曝光機會。

可以讓使用者選擇：

- 全台隨機
- 限定地區
- 狗狗
- 貓咪
- 不限種類

但不要增加過多複雜條件，破壞相遇的驚喜感。

## 4.5 禁止稀有度制度

不要將動物分成：

- SSR
- SR
- R
- N

不要按照品種、年齡、外觀、毛色或健康狀態給予價值排名。

沒有任何動物應該被標示為比較差的獎品。

本作品的轉蛋只是讓使用者以有趣的方式認識動物。

不是將動物商品化。

# 05｜相遇卡片

轉蛋打開後，會出現一張漂亮的動物相遇卡。

## 5.1 美術方向

希望像：

**一張具有絹印風格的動物紀念卡，結合真實照片與幾何插畫。**

可以有：

- 大張動物照片
- 色塊邊框
- 動物編號
- 少量裝飾圖形
- 可愛的印章
- 簡潔的資訊

但不能只是將照片放進普通的圓角卡片。

應該具有收藏插畫的美感。

## 5.2 重要資料

至少顯示：

- 動物照片
- 動物類型
- 收容編號
- 所在縣市
- 收容所名稱
- 年齡分類
- 性別
- 毛色
- 目前認養狀態

其他資料可以展開查看。

## 5.3 動物名字

如果官方資料有名稱，優先使用。

如果沒有名稱：

請使用：

「編號 XXXX 的小朋友」

或其他溫暖、但不會令人誤認是真名的稱呼。

不要自行替動物建立假的正式名字。

可以在視覺上使用可愛的描述，例如：

「今天遇見的黑色狗狗」

但應明確區分正式資料與作品文案。

## 5.4 真實照片

動物照片是很重要的核心內容。

不得使用 AI 生成的動物照片假裝是收容動物本人。

如果照片缺失：

請使用一致、可愛的幾何插圖作為替代。

並標示：

「目前沒有照片」

不能使用另一隻真實動物的照片來替代。

# 06｜動物圖鑑

除了轉蛋，網站還要有可以自由探索的動物圖鑑。

## 6.1 圖鑑形式

我希望它像一本可以翻閱的插畫書。

可以有：

- 翻頁
- 分類索引
- 動物照片
- 角色資訊
- 小小的印章
- 色塊標籤

但不要用複雜動畫犧牲操作效率。

## 6.2 搜尋條件

至少包含：

- 地區
- 動物類型
- 年齡分類
- 性別
- 體型
- 收容所

可以有：

- 有照片
- 最新開放認養
- 最近更新

但不要把「年紀較大」「外貌不受歡迎」等推測分類直接套到動物身上。

## 6.3 圖鑑卡片

每張卡片應保持：

- 精緻
- 簡潔
- 圖像優先
- 容易比較
- 清楚的行動入口

必須有合理的 Loading、Empty 和 Error 狀態。

## 6.4 全國資料量

農業部資料量可能較大。

請研究：

- API 分頁
- 後端快取
- 前端分頁
- 圖片 Lazy Loading
- 列表效能
- 篩選效率

不要每次操作都重新下載全國所有資料。

# 07｜動物故事頁

這是另一個最重要的體驗。

我希望使用者可以真正停下來，仔細認識一隻動物。

## 7.1 故事頁構圖

請設計成：

**一頁具有情感的互動插畫故事。**

主角是真實動物照片。

旁邊可以搭配：

- 色塊插畫
- 小花
- 腳印
- 幾何造型
- 動物資訊
- 原始資料中的故事線索

不要使用普通資料表作為主要畫面。

## 7.2 故事來源

非常重要：

不能捏造真實動物的經歷。

例如：

如果官方只有：

「成年、黑色、母犬、位於某收容所」

不能擅自寫成：

「牠曾經被主人拋棄，現在每天都在等待有人帶牠回家。」

因為這些事情沒有資料支持。

## 7.3 可以使用的敘事

可以用有溫度、但不捏造事實的文字。

例如：

「今天，讓我們認識這位朋友。」

「牠目前在台南的收容所。」

「牠是一隻成年的黑色狗狗。」

「想多了解牠，可以聯絡收容所。」

如果備註裡有真正的性格描述，可以引用或忠實改寫。

但應清楚標示資料來源。

## 7.4 不要推測性格

不能單純看照片，就聲稱：

- 個性很親人
- 喜歡小孩
- 適合新手
- 不會咬人
- 喜歡其他動物

除非有可靠的資料來源。

如果沒有性格資訊：

可以寫：

「想知道牠的個性嗎？可以向收容所詢問。」

## 7.5 等待時間

可以研究利用：

`animal_createtime`

或：

`animal_opendate`

呈現相關日期。

但不要把資料建立日期直接稱為入所日期。

也不要把開放認養日期直接等同於入所日期。

如果要顯示「已等待幾天」，必須先確認計算基準。

建議初版使用：

「自 YYYY/MM/DD 開放認養」

而不是假裝知道真正的收容等待天數。

# 08｜收藏：我的相遇小冊子

我希望使用者能保存自己喜歡的動物。

但不要做成需要全部蒐集完成的遊戲。

## 8.1 收藏形式

可以設計成一本：

**「我的相遇紀錄」**

每次收藏一隻動物，就像貼上一張小小的印刷卡片。

可以使用：

- 印章
- 色塊貼紙
- 翻頁
- 收藏冊
- 小型動物照片

延續我的集章網站美學。

## 8.2 收藏資料

第一版可以使用 LocalStorage。

保存：

- 動物 ID
- 收藏時間
- 必要的最小識別資訊

不需要登入系統。

不要儲存大量不必要的個人資訊。

## 8.3 動物已不在資料集

當收藏的動物不再出現在官方資料：

不能直接顯示：

「恭喜！已成功被認養！」

因為牠可能因不同原因出所或資料變更。

請顯示：

「目前無法在最新公開資料中找到這位朋友。」

並引導使用者向收容所確認。

可以保留收藏紀錄，但必須明確標記狀態未確認。

## 8.4 不建立完成率壓力

不需要：

- 全圖鑑收集率
- 稀有動物獎勵
- 連續轉蛋登入獎勵
- 抽蛋排行榜
- 抽蛋付費機制

收藏是為了記住相遇。

不是為了追求遊戲分數。

# 09｜提高真正的認養意願

這個作品的最終目的，是讓更多動物有機會被認識。

請設計清楚、自然的行動路徑。

## 9.1 動物詳細頁行動

至少包含：

### 我想進一步認識牠

帶領使用者查看：

- 所屬收容所
- 所在地
- 聯絡電話
- 官方認養查詢方式
- 相關認養資訊

### 收藏這次相遇

加入收藏小冊子。

### 分享這位朋友

建立適合分享的內容。

## 9.2 官方資訊

不得自行捏造動物的專屬認養網址。

如果官方能找到可靠、可用且與動物 ID 對應的詳情頁：

才建立專屬連結。

否則：

- 提供官方認養查詢入口。
- 附上動物收容編號。
- 提供所屬收容所資訊。
- 告訴使用者如何查詢。

## 9.3 認養前的準備

可以設計一個非常簡潔的：

「帶牠回家之前」

資訊入口。

內容包含：

- 了解照顧需求
- 考慮居住環境
- 考慮長期時間與經濟責任
- 與收容所確認健康及個性
- 了解正式認養程序

不要將認養流程設計得像網購結帳。

最重要的是負責任的認養，而不是衝動決定。

## 9.4 不使用過度情緒勒索

避免：

- 不認養就會害牠怎樣
- 最後一次機會
- 只剩幾小時
- 今天不救牠就來不及

這些未經證實且會增加壓力的文案。

請讓使用者因為真正認識動物而產生連結。

# 10｜轉蛋後的小小故事

我希望轉蛋有一些隨機但不干擾真實資訊的趣味文案。

例如：

轉蛋打開：

「咦！有人來了！」

相遇卡出現：

「今天遇見的是一位來自高雄的朋友。」

使用者收藏：

「這次相遇，已經記在小冊子裡了。」

使用者選擇繼續：

「好呀！再去認識下一位朋友。」

使用者關閉：

「今天的相遇就先到這裡。」

NPC 的台詞可以有溫柔的幽默感。

但不能替真實動物虛構內心獨白，讓人以為那是牠真正的想法。

# 11｜分享圖片

這個作品應該有漂亮的分享機制。

請建立：

**相遇紀念卡分享圖**

## 11.1 分享圖內容

至少包含：

- 真實動物照片
- 動物編號或資料標題
- 動物類型
- 所在縣市
- 收容所名稱
- 作品名稱
- 查詢資訊或可用的認養入口

## 11.2 美術風格

像一張精美的小型絹印海報。

使用：

- 大色塊
- 少量字體
- 可愛圖形
- 清楚構圖
- 真實照片

不要把所有欄位都塞進分享圖片。

## 11.3 分享功能

支援：

- 儲存 PNG
- Web Share API（若支援）
- 複製分享連結
- 桌面與手機版

## 11.4 分享連結

分享網址應能重新開啟相同動物的介紹。

例如可使用：

`/animal/{id}`

但請先驗證資料 ID 的穩定性、唯一性與路由設計。

如果動物已不在最新資料中，必須顯示適當的狀態說明。

## 11.5 QR Code

如果適合，可以加入小型 QR Code。

但 QR Code 必須導向真實可用的網址。

不得產生假的認養網址。

## 12.1 資料欄位

- `shelter_address`
- `shelter_tel`

請以實際回傳資料為準。

不要假設所有欄位都有值。

## 12.2 資料量與更新

官方建議大型資料集分批取得，每批約 1000 筆。

請研究官方 API 的分頁、查詢與限制。

建立合理的快取更新機制。

資料標示每日更新，但不代表每隻動物的資訊都會每分鐘更新。

## 12.3 狀態判斷

請實際研究 `animal_status` 的定義。

例如 `OPEN` 等狀態。

不能只看到 `OPEN` 就忽略其他資料限制。

也要確認：

- 開放認養日期
- 資料是否仍有效
- 狀態是否有變動
- 動物是否仍出現在資料集

不能將資料消失直接解釋成「成功認養」。

## 12.4 圖片處理

請研究 `album_file`。

確定：

- 照片網址是否有效
- 是否允許跨網域載入
- 是否支援 HTTPS
- 是否需要圖片代理
- 無照片時怎麼處理
- 圖片失效時怎麼處理

不要抓取其他網站的動物照片作為替代。

## 12.5 資料安全

如果使用者輸入搜尋條件，必須避免不安全的查詢或輸出。

對官方備註內容進行必要的文字清理。

不要把外部來源的 HTML 直接當成可信內容插入 DOM。

# 18｜動物福利與內容原則

這個章節具有最高優先級。

## 不得做的事情

1. 不得替真實動物編造悲慘身世。
2. 不得虛構性格、健康狀態或行為特徵。
3. 不得用 AI 假照片取代真實收容動物照片。
4. 不得把動物用稀有度排名。
5. 不得使用強迫、恐嚇或情緒勒索文案。
6. 不得以動物外貌評斷認養價值。
7. 不得把出所誤報為已認養。
8. 不得偽造成功認養數據。
9. 不得建立無法驗證的個別認養連結。
10. 不得讓使用者以為在本站按一下就完成正式認養。

## 我希望達成的事情

- 讓更多人看見真實收容動物。
- 讓使用者願意認識不同年齡與外貌的動物。
- 讓動物資訊更容易被理解。
- 降低尋找認養資訊的門檻。
- 增加收藏與分享。
- 幫助使用者找到正確的收容所聯絡方式。
- 鼓勵負責任的認養行為。

**轉蛋是相遇的入口，不是整個網站的終點。**

# 20｜成功指標

本作品的目標不是提高抽蛋次數而已。

請將成功指標分成三類。

### 體驗指標

- 使用者是否願意探索動物。
- 是否查看完整動物介紹。
- 是否收藏相遇卡。
- 是否願意分享。

### 實際行動指標

- 有多少使用者點擊收容所聯絡資訊。
- 有多少使用者進入正式認養查詢。
- 有多少使用者閱讀認養前須知。

### 資料品質指標

- API 更新是否正常。
- 失效資料是否妥善處理。
- 動物資料是否正確。
- 照片是否正常顯示。

如果未來希望追蹤實際認養成果，需要和官方或收容所合作確認，不能只根據網站點擊數推估成功認養數。

如果加入匿名分析，也應尊重隱私、遵守相關規範，避免不必要的個人追蹤。

# 22｜最終創作理念

請始終記住：

**這不是一個加上轉蛋動畫的認養資料庫。**

這是一間讓真實動物與使用者產生連結的小小相遇所。

我想像有人走進網站。

櫃檯後的小站務員正在發呆。

看到訪客，牠突然精神起來：

「啊！歡迎光臨！今天想認識誰呢？」

使用者轉動轉蛋機。

一顆小膠囊掉了下來。

打開之後，是一張漂亮的動物相遇卡。

畫面上出現一隻真正住在台灣某間收容所的狗狗。

使用者發現牠的耳朵很可愛。

於是點開介紹。

又發現牠其實就在自己住的縣市。

於是收藏了牠，並且點開收容所的聯絡資訊。

也許今天只是認識。

也許之後會去看看。

也許有一天，這個相遇真的能成為一段共同生活的開始。

**我希望網站擁有足夠的美術魅力、互動樂趣和故事感，讓更多真實的動物有機會被看見。**

請以「高品質美術 × 真實可靠資料 × 真正有助於認養」為最高目標開始實作。
