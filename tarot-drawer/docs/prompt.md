# PROJECT BRIEF
# THE LITTLE TAROT PRESS
## 小小塔羅印刷所 — An Interactive Tarot Drawing Tool

你是一位兼具以下能力的資深創作型工程師：

- Creative Front-end Developer
- UI / UX Designer
- Interactive Art Director
- Motion Designer
- Illustrator
- Tarot System Researcher

請為我從零開始設計並開發一個完整、精緻、可實際使用的塔羅抽牌網站。

這不是一般的 CRUD 網站，也不是套用現成 UI Template 的普通工具。

我希望你把它當作一件具有完整美術風格與互動設計的 **Digital Interactive Artwork（數位互動藝術作品）**。

但請注意：

**藝術感不能犧牲工具的實用性。**

本作品的核心功能，是讓使用者透過漂亮、自然、有儀式感的介面，完成真正符合塔羅抽牌基本規則的抽牌流程。

# 01｜PROJECT IDENTITY

## 作品名稱

暫定：

**THE LITTLE TAROT PRESS**

中文名稱：

**小小塔羅印刷所**

名稱只是工作名稱。

請將網站名稱集中管理，方便未來修改。

## 核心概念

> 一個藏在網路角落的小小塔羅印刷所。
>
> 使用者來到這裡，洗牌、選牌、翻牌。
>
> 然後得到一張像剛從復古印刷機印出來的塔羅牌。
>
> 沒有冗長的占卜報告。
>
> 沒有神祕兮兮的 AI 占卜師。
>
> 只有牌、基礎意涵，以及一場精緻的小小儀式。

## 產品定位

這是一個：

**極簡 × 可愛 × 絹印美術 × 互動式塔羅抽牌工具**

不是：

- AI 解牌網站
- 塔羅教學百科
- 戀愛占卜網站
- 運勢預測服務
- 角色扮演遊戲
- 劇情探索遊戲
- 抽卡養成遊戲
- 每日簽到系統

不要自行加入上述功能。

## 最重要的設計原則

**Keep it simple, but make every interaction delightful.**

操作必須簡單。

視覺必須精緻。

動畫必須自然。

抽牌規則必須正確。

每個細節都應該有存在的理由。

# 02｜VISUAL DIRECTION

## 整體美術方向

請使用以下元素建立一致的視覺語言：

**RISO PRINT × JAPANESE EDITORIAL × CUTE MINIMALISM × VINTAGE TAROT**

中文理解：

- RISO 孔版印刷
- 復古絹印
- 日系獨立出版物
- 極簡可愛插畫
- 復古塔羅卡片
- 少量幽默
- 安靜但有生命力的互動

希望整體看起來像：

一家小型獨立印刷工作室製作的原創塔羅牌。

而不是常見的紫色漸層神祕占卜網站。

## 2.1 色彩

請建立一套具有印刷感的有限色盤。

建議以以下色彩作為起點：

- Warm Paper：溫暖的米白色
- Ink Navy：深藍黑色
- Vermilion：朱紅／橘紅
- Butter Yellow：奶油黃
- Muted Blue：柔和藍色

不需要每張牌都使用全部顏色。

每張牌可以有自己的主色組合。

但整套牌必須共享一致的印刷語言。

### 色彩限制

不要使用：

- 大量霓虹色
- 通用科技感紫色漸層
- 過量發光效果
- 高飽和 RGB 彩虹
- 玻璃擬態 Dashboard
- AI SaaS 產品常見的漸層卡片介面

整體應該有實體印刷品的美感。

## 2.2 RISO 印刷質感

可以適度使用：

- Halftone 網點
- 色版錯位
- 疊色
- 不規則油墨邊緣
- 局部印刷顆粒
- 紙張肌理

但需要注意：

**印刷效果必須經過設計，而不是整張圖片疊一層雜訊。**

例如：

紅色與藍色圖層輕微錯位。

錯位處形成自然疊色。

網點密度隨陰影變化。

不同色版有細微的不完美。

### 重要

這些效果應該保持克制。

不要降低文字辨識度。

不要讓整體看起來髒亂。

## 2.3 插畫風格

請為塔羅牌建立一套原創插畫語言。

風格要求：

- 簡潔
- 可愛
- 有角色感
- 幾何造型
- 有印刷感
- 構圖完整
- 適合縮小觀看
- 顏色數量有限

角色可以很簡單。

例如：

圓圓的太陽。

歪歪的月亮。

安靜提燈的人。

背著背包的小生物。

穿著斗篷的骷髏。

但不要讓角色設計過度幼兒化。

希望保留一點復古塔羅原有的神祕感與象徵性。

### 不要直接生成 22 張毫無關聯的插畫

請先建立：

1. 統一的卡片比例
2. 統一的邊框設計
3. 統一的線條粗細
4. 統一的角色比例邏輯
5. 統一的色彩系統
6. 統一的印刷處理
7. 統一的文字與牌號配置

再進行個別插畫設計。

**整套牌必須看起來是同一位藝術家設計的。**

# 04｜DRAW SETTINGS

使用者可以在抽牌前設定參數。

第一版提供：

## 4.1 抽牌張數

選項：

**ONE CARD**

抽一張牌。

**THREE CARDS**

抽三張牌。

預設：

ONE CARD

## 4.2 逆位設定

選項：

**REVERSALS OFF**

只出現正位。

**REVERSALS ON**

允許出現正位及逆位。

預設：

OFF

### 技術規則

逆位開啟時，每張牌應有獨立且公平的正逆位判定。

預設可使用 50% 正位、50% 逆位。

不要根據牌義、抽牌位置或使用者操作方式偷偷調整機率。

請使用 Web Crypto API，例如 `crypto.getRandomValues()`，取得適合抽牌用途的隨機值，並避免明顯的模數偏差。

## 4.3 三張牌陣

當選擇 THREE CARDS 時，提供：

### SPREAD A

PAST / PRESENT / FUTURE

過去／現在／未來

### SPREAD B

SITUATION / OBSTACLE / ADVICE

現況／阻礙／建議

預設：

PAST / PRESENT / FUTURE

選擇單張牌時，隱藏三張牌陣設定。

### 重要

牌陣位置只作為結果的標籤。

不需要自動產出三張牌之間的完整解讀。

例如：

PAST

XVII THE STAR

希望、療癒、信任

這樣就足夠。

# 05｜DRAWING MECHANICS

這是網站的核心。

抽牌不是單純按下按鈕後顯示隨機圖片。

請製作完整但不冗長的抽牌體驗。

## 5.1 初始狀態

使用者進入網站後，看到：

- 網站名稱
- 一疊背面朝上的塔羅牌
- 簡潔的抽牌設定
- 主要操作按鈕

畫面不要有大量文字。

牌堆應該是視覺中心。

## 5.2 洗牌

點擊：

**SHUFFLE THE DECK**

開始洗牌動畫。

希望看到：

牌張稍微分離。

向左右錯開。

交錯移動。

重新堆疊。

不需要模擬極度寫實的撲克牌物理。

但動畫必須有可信的牌張移動感。

### 洗牌機制

真正的隨機洗牌應該在資料層完成。

動畫只是呈現。

請使用正確的隨機洗牌演算法，例如 Fisher–Yates Shuffle。

隨機來源應使用 Web Crypto API。

不得以動畫中的視覺順序代替真正的資料洗牌。

## 5.3 展牌

洗牌完成後，將牌背展開。

可以使用：

- 扇形排列
- 橫向弧形排列
- 桌面散牌排列

請由你根據整體美術方向選擇最適合的設計。

但必須兼顧：

- 桌面電腦
- 手機
- 觸控操作
- 可選擇性
- 動畫流暢度

我偏好：

**帶有弧度的扇形牌堆。**

### 手機版

不要直接將桌面版扇形縮小。

請重新設計適合觸控的操作方式。

例如：

水平拖曳牌堆。

中央的牌略微浮起。

點擊選擇。

確保使用者不會因牌張重疊而難以選取。

## 5.4 選牌

使用者可以自由選擇某一張牌。

不能只是表面上讓使用者選，實際上卻早已隨機決定結果。

正確做法：

先建立隨機排列的牌堆。

每張背面卡片對應一張真實卡牌。

使用者選中的位置，就得到該位置對應的卡牌。

### 三張模式

使用者需要選擇三張不同的牌。

已選過的牌不能再次被抽中。

抽完第一張後，剩餘牌堆保留。

繼續抽第二張。

再抽第三張。

### 抽牌順序

抽到的第一張對應牌陣位置一。

第二張對應位置二。

第三張對應位置三。

順序不得在結果頁被重新排序。

## 5.5 翻牌

抽中的牌從牌堆移動到指定位置。

接著翻到正面。

請設計有紙牌實體感的翻牌動畫。

可使用：

- CSS 3D Transform
- Perspective
- Spring Animation
- Smooth Easing

動畫不要像普通網頁翻轉卡片那樣僵硬。

我希望它有輕微的重量與慣性。

### 逆位

若抽中逆位，卡片正面應顯示旋轉 180° 的方向。

但結果文字必須維持正常閱讀方向。

不要把整個 UI 一起倒過來。

顯示三張牌。

桌面版：

三張橫向排列。

手機版：

# 07｜SHAREABLE POSTER

這個功能非常重要。

請把結果圖片當成一張完整的原創平面設計作品。

不是直接截圖網站畫面。

## 7.1 單張分享圖

分享圖應包含：

- 原創塔羅插畫
- 牌號
- 中英文牌名
- 正位或逆位
- 基礎關鍵字
- 抽牌日期
- 網站名稱／小印章

整體視覺像：

**一張精緻的復古絹印塔羅海報。**

### 建議比例

直式。

可以使用：

1080 × 1620 px

或其他適合完整呈現卡牌構圖的直式比例。

## 7.2 三張分享圖

三張牌必須出現在同一張圖片中。

這不是三張單張分享圖的拼接。

請重新設計適合三張牌的版面。

例如：

上方：

THREE CARD DRAW

中間：

三張縮小的塔羅牌。

各自附上：

PAST / PRESENT / FUTURE

下方：

日期與印刷所的小標記。

### 關鍵

單張和三張模式應有不同的版面設計。

但共享相同視覺系統。

## 7.3 印刷細節

分享圖可以加入：

- 紙張背景
- 小型套色標記
- 印刷編號
- 細微錯位效果
- 小印章
- 日期戳記

但不要太花俏。

### 隨機印刷細節

可以為每次結果加入少量隨機的色版錯位或紙張紋理。

但同一次抽牌的結果必須保持一致。

不可每次按下下載就重新生成不同的版面或圖像。

## 7.4 圖片匯出品質

請確保：

- 解析度足夠
- 文字清楚
- 字體正確載入
- 不會裁切牌面
- 不會出現跨網域圖片污染 Canvas 的問題
- 手機瀏覽器可以保存
- iOS Safari 可以正常操作

可使用 Canvas 或 SVG 輸出。

若使用 DOM 截圖方案，必須充分測試。

### 優先建議

使用 SVG 建立可控的海報排版，再輸出 PNG。

確保畫面與下載圖片的一致性。

### 重要

如果卡片結果是逆位，海報中的卡牌也必須維持逆位。

不要在下載圖裡偷偷轉正。

這部分是本作品最重要的美術任務之一。

## 8.1 原創 22 張牌

請為 22 張大阿爾克那建立一套完整的原創塔羅牌。

不要從網路直接下載既有塔羅插畫充當成品。

不要直接使用傳統偉特塔羅的原始構圖圖片。

可以研究傳統塔羅象徵，但應重新創作。

女祭司

一個安靜的小角色坐在兩根柱子之間。

旁邊有月亮與書本。

直覺、潛意識、隱藏的知識。

### VI THE LOVERS

### XXI THE WORLD

世界

一個小生物站在植物、星星與幾何圖案組成的環形構圖中央。

## 8.3 其餘牌面

請自行研究所有剩餘牌面的重要象徵。

建立完整的設計。

不要把未提供參考的牌面做成隨意的通用圖案。

每張卡片必須具有：

**可辨識的象徵主題。**

## 8.4 素材製作方式

請依照實際可用工具選擇：

- SVG 原創繪圖
- 程式化向量插畫
- Canvas Illustration
- 可合法使用的生成式圖像

優先考慮 SVG。

因為 SVG：

- 容易統一視覺
- 適合 RISO 色塊
- 可保持解析度
- 易於製作動畫
- 易於輸出分享圖片

### 重要限制

不要使用 Emoji 代替牌面插畫。

不要使用一般 Icon Library 圖示拼湊成 22 張牌。

不要使用同一個角色輪廓，只替換背景或文字，假裝完成不同牌面。

我希望它們是真正設計過的原創卡片。

若環境無法直接生成高品質美術素材，請清楚區分已完成插畫與待製作素材，不得以低品質佔位圖宣稱完成整套牌。

牌背是一個非常重要的視覺元素。

# 10｜INTERACTION & MOTION DESIGN

動畫品質是本作品的重要評估項目。

但請避免炫技。

## 10.1 動畫原則

希望動畫具有：

- 物件重量感
- 適當的慣性
- 柔和的停頓
- 清楚的操作回饋
- 細緻的時間控制

不要所有動畫都使用相同的 ease-in-out。

應根據不同動作調整。

例如：

洗牌：較活潑。

展牌：流暢、有秩序。

選牌：立即回應。

翻牌：稍微慎重。

結果呈現：平靜。

## 10.2 動畫時間

請控制整體節奏。

建議：

- 洗牌：約 1～2 秒
- 展牌：約 0.5～1 秒
- 抽牌：約 0.3～0.6 秒
- 翻牌：約 0.5～0.8 秒

這些是設計參考，不是硬性限制。

### 重要

不要讓使用者每次抽牌都必須觀看長達十幾秒的固定動畫。

重複操作時應維持順暢。

## 10.3 音效

可選擇加入非常細微的：

- 紙張滑動聲
- 洗牌聲
- 翻牌聲
- 印章聲

但預設可以保持靜音。

提供 Sound ON / OFF。

不要強制播放背景音樂。

音效不是第一版的必要條件。

## 10.4 Reduced Motion

請支援：

`prefers-reduced-motion`

使用者若偏好減少動畫，仍應可以完成所有抽牌操作。

不得因停用動畫導致狀態卡住。

# 14｜DRAW ENGINE IMPLEMENTATION

type TarotCard = {

  romanNumeral: string;
  nameZh: string;
  nameEn: string;
  meaning: string;
  uprightKeywords: string[];
  reversedKeywords: string[];
  artwork: string;

  orientation: "upright" | "reversed";
  position: number;

請正確實作：

7. 畫面動畫不會重新觸發隨機抽牌。

### 重要

不要把隨機抽牌寫在 React Render 階段。

不要因為元件重新渲染就改變牌面。

不要為了動畫效果在多個地方重複呼叫隨機函數。

請將抽牌結果與視覺呈現分離。

開始抽牌後，設定暫時鎖定。
