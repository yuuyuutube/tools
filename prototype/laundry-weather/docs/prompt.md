# 04. 最重要的互動：衣服隨風擺動

這是本專案的核心動畫。

我希望衣服看起來真的被微風吹動。

不是簡單地讓整件衣服左右平移。

## 4.1 基本動畫

衣服掛在衣夾上。

以衣夾附近作為主要旋轉支點。

衣服緩慢左右擺動。

不同衣服具有不同的：

- 擺動幅度
- 擺動週期
- 相位
- 慣性
- 布料變形程度

不能所有衣服完全同步搖晃。

否則看起來會很機械。

## 4.2 風速對動畫的影響

根據真實風速改變動畫。

### 無風

衣服幾乎不動。

只有極小幅度的自然微動。

### 微風

衣服輕輕左右擺動。

這應該是最療癒的狀態。

### 中等風速

衣服擺動比較明顯。

偶爾出現輕微布料波動。

### 強風

衣服擺動加大。

但必須避免誇張、不舒服的高速旋轉。

必要時可以出現：

「今天風有點大，衣服要夾好喔！」

這種簡短提示。

## 4.3 動畫技術

優先使用：

- SVG
- CSS Transform
- Web Animations API
- requestAnimationFrame（必要時）

不必為了簡單動畫引入大型動畫套件。

可以自行設計少量程序化動態。

允許結合：

- 正弦波
- 不同頻率
- Perlin Noise 或平滑雜訊
- 阻尼
- 慣性

但請以實際視覺效果為優先。

## 4.4 最重要的原則

**真實風速決定動畫趨勢，藝術設計決定動畫的優雅程度。**

不能因為風速高，就讓衣服瘋狂晃動。

動畫需要適合長時間觀看。

# 05. 天氣與場景變化

至少設計以下四種場景。

## SCENE A：晴朗好天氣

- 明亮天空
- 溫暖陽光
- 衣服輕輕擺動
- 適度的雲朵
- 清爽而舒服

文字範例：

「今天很適合曬衣服！」

## SCENE B：多雲

- 天空比較柔和
- 雲朵增加
- 陽光偶爾被遮擋
- 衣服維持自然晃動

文字範例：

「今天可以曬，但可能要多晾一會兒。」

## SCENE C：潮濕

- 配色略微沉靜
- 空氣感比較厚重
- 衣服動畫可以稍微顯得沉重

文字範例：

「今天有點潮濕，衣服可能比較難乾。」

## SCENE D：下雨或高降雨風險

- 雨滴以簡潔色塊或線段呈現
- 雲朵有不同的視覺狀態
- 可以讓衣物略微呈現潮濕的視覺效果

文字範例：

「今天先不要把衣服晾在外面喔。」

重要：

場景必須根據資料變化。

不能只是隨機切換。

但藝術細節可以在合理範圍內隨機產生。

# 07. GPS 與城市選擇

## 7.1 初次進站

網站嘗試取得使用者的位置。

注意：

Geolocation API 通常需要 HTTPS 或 localhost。

需要妥善處理權限請求。

## 7.2 GPS 判定

取得經緯度後，選擇適合的氣象預報行政區域。

優先使用：

**距離最近或實際所屬的鄉鎮預報區域。**

不能單純找最近的氣象站，就假設該測站代表使用者所在城市。

觀測站與預報區域應分開處理。

## 7.3 GPS 失敗

如果使用者：

- 拒絕定位
- 裝置不支援
- GPS 逾時

請提供手動城市選擇功能。

不要讓畫面停留在錯誤狀態。

預設可顯示台北市的示範場景，但必須明確標示目前是預設地點，不能假裝使用者真的在台北。

## 7.4 隱私

不儲存使用者精確 GPS 座標。

不傳送給不必要的第三方。

可以儲存使用者手動選擇的城市。

# 09. 晾衣適宜度判斷

這個網站的重要功能是根據天氣給出建議。

但不能把它包裝成官方氣象指數。

請自行建立：

**Laundry Suitability Score**

晾衣適宜度分數。

這是一個本網站自行計算的生活參考指標。

不是中央氣象署官方發布的指標。

## 9.1 考慮因素

優先考慮：

1. 降雨機率
2. 目前是否下雨
3. 相對濕度
4. 風速
5. 氣溫
6. 天氣現象
7. 接下來幾小時的天氣

## 9.2 基本原則

### 降雨風險

降雨風險高時，應明顯降低戶外晾衣推薦程度。

### 濕度

濕度越高，通常越不利於衣物乾燥。

### 風速

適度通風有利於乾燥。

但強風可能造成衣物掉落或其他問題。

不能認為風越大就一定越適合晾衣。

### 氣溫

較高氣溫通常有利於蒸發，但不能忽略濕度與降雨。

## 9.3 分級

建議至少分成四個等級。

### GREAT

非常適合晾衣

### GOOD

適合晾衣

### FAIR

可以晾，但乾燥速度可能較慢

### POOR

不建議戶外晾衣

請自行設計合理的初始規則。

必須把：

- 計算方法
- 權重
- 門檻
- 資料不足時的處理方式

獨立封裝並撰寫文件。

所有門檻都應標記為本作品的初始啟發式規則，而非經過實測驗證的乾燥模型。

## 9.4 不要假裝可以精確預測晾乾時間

衣服乾燥速度還受到：

- 衣物材質
- 厚度
- 脫水程度
- 日照
- 通風環境
- 室內或戶外

等因素影響。

第一版不要輸出：

「衣服將在 87 分鐘後乾燥」

這種缺乏依據的精確數字。

可以使用：

「可能乾得比較快」

「今天可能需要多晾一會兒」

這種合理的定性描述。

另外，**降雨機率一定要對應正確的預報時間區間**，不得把下午的降雨機率當作現在的即時數值。

# 10. 畫面如何根據資料變化

請建立一個：

**Weather → Visual Mapping System**

讓資料真正驅動畫面。

例如：

| 資料 | 視覺變化 |
|---|---|
| 風速 | 衣物擺動幅度 |
| 風向 | 衣物受風方向 |
| 濕度 | 天空色彩與場景氛圍 |
| 雲量／天氣現象 | 雲朵與陽光呈現 |
| 降雨 | 雨滴動畫 |
| 日夜 | 天空配色 |
| 晾衣適宜度 | 主要建議文字與場景情緒 |

注意：

如果 API 沒有提供雲量或日照數據，不要自行宣稱取得了真實雲量。

可以用天氣現象做藝術上的概略呈現，但需與真實觀測數值區分。

## 10.1 數值變動時

不要讓畫面突然切換。

例如風速由 2 m/s 變成 4 m/s。

衣服的擺動應該緩慢過渡。

晴天變成多雲，也應有柔和的轉場。

## 10.2 長時間觀看

畫面不能每隔幾秒就出現劇烈變化。

我希望有：

- 微小的自然變化
- 緩慢移動
- 不完全重複的節奏
- 柔和的資料過渡

這是一個可以長時間打開的作品。

不是一個一直試圖吸引注意力的廣告動畫。

# 11. 小小的驚喜

我希望網站有少量讓人會心一笑的細節。

但請保持整體構圖的品質。

**這些驚喜只能是配角。**

不要搶走天氣資料與晾衣場景的主題。
