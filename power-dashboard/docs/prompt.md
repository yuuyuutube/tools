# 01｜最重要：美術方向

## 1.1 參考我的既有作品

請優先尋找並檢查我現有的「絹印＆集章網站」。

參考專案可能包含：

- `/tools/retro-printer`
- `/tools/stamp-tour`

這些路徑只是先前的參考資訊，請先確認是否實際存在。

另外，我可能會提供 Laundry Weather 的美術參考圖片。

如果能讀取，請研究：

- 色塊輪廓
- 色彩比例
- 插圖簡化程度
- 幾何造型
- 印刷質感
- 留白與視覺節奏

如果無法找到參考作品，不得假裝已經看過。

## 1.2 美術語言

我希望延續：

**極簡、可愛、幾何大色塊、絹印感、漂亮的平面圖像設計。**

關鍵字：

- Minimal Geometric Illustration
- Bold Flat Shapes
- Silkscreen / Risograph Inspired
- Playful Editorial Illustration
- Japanese Graphic Design
- Cute Industrial Architecture
- Animated Paper Cutout
- Kinetic Illustration
- Whimsical Little World

不要使用：

- 科幻控制台
- Cyberpunk
- 3D 擬真電廠
- 等距 3D 城市
- Glassmorphism
- 大量漸層
- 高科技藍光介面
- 普通 SaaS Dashboard
- 卡片內塞滿文字和圖表

**視覺主體必須是插畫，而不是 UI 元件。**

## 1.3 配色原則

不要把六間發電廠全部做成高彩度配色。

每個發電廠可以擁有不同色相和主題色。

例如：

| 發電廠 | 配色方向 |
|---|---|
| 燃氣 | 霧紫、淡橘、奶油白 |
| 燃煤 | 深磚紅、灰褐、米色 |
| 太陽能 | 奶油黃、磚粉、柔和綠 |
| 風力 | 鼠尾草綠、淡紫、米白 |
| 水力 | 霧藍綠、深綠、淡黃 |
| 其他能源 | 芥末黃、灰紫、深褐 |

這些只是探索起點。

請自行研究配色，使六座發電廠：

- 各自有辨識度。
- 放在一起又很協調。
- 有高、中、低彩度變化。
- 有適當的明度對比。
- 不會全部都在搶注意力。

**絹印風格不等於每個顏色都要非常鮮豔。**

優先使用有限色盤、乾淨色塊與極少量印刷質感。

# 02｜核心畫面：六宮格發電廠

桌面首頁以六宮格為主。

3 欄 × 2 列。

六個區塊共同形成一座可愛的虛擬發電世界。

## 2.1 每個格子的內容

每個區塊都必須包含：

1. 一座具有鮮明造型的虛擬發電廠。
2. 持續運作的精緻動畫。
3. 能源名稱。
4. 目前發電功率。
5. 發電占比。
6. 一位 NPC 或可愛角色。
7. 可依條件出現的角色台詞。

數值資訊應融入插畫，不要破壞畫面。

## 2.2 六宮格構圖

我不希望是六張普通的資訊卡。

我希望每一格都像一幅獨立的動態絹印插畫。

例如：

太陽能廠的天空較明亮。

風力廠有大面積風車。

水力廠有簡潔的水壩和水流。

燃煤廠有非常有辨識度的工業輪廓。

它們都是一個小世界，但共享同樣的設計語言。

六格之間可以有適度留白與分隔。

避免過多邊框、陰影與卡片裝飾。

## 2.3 全屏觀賞模式

桌面版應可以切換成觀賞模式。

在這個模式裡：

- 六座發電廠是畫面主角。
- 隱藏次要資訊與操作介面。
- 保留必要的名稱、數值和整體供電狀態。
- 動畫持續自然運作。
- NPC 偶爾對話。
- 不需要操作也能享受整個作品。

這個模式應該像六幅會動的插畫共同組成的展示牆。

# 03｜六座發電廠的角色設計

請為每座發電廠建立獨立的美術概念。

注意：這六間都是虛構的「能源類型代表」，不是實際存在的六座建築。

## 01. 燃氣發電廠

暫定性格：勤奮、可靠、有點忙碌。

### 美術

- 圓潤的工業建築。
- 簡潔的管線與煙囪。
- 渦輪或機械零件。
- 少量重複的機械動態。

### 動畫

- 渦輪旋轉。
- 管線中的色塊流動。
- 機械設備輕輕震動。
- 發電功率提高時，運作節奏略微增加。

不要把水蒸氣、廢氣排放或污染程度直接映射為發電數字；這些並不是同一種資料。

### NPC

一位很認真工作的工廠小員工。

可能的台詞：

「今天也有好多工作要做呢！」

「大家都在用電，我可不能偷懶！」

「呼～先把這一批電送出去！」

---

## 02. 燃煤發電廠

暫定性格：沉穩、傳統、像老工匠。

### 美術

- 方正但可愛的大型廠房。
- 幾根粗大的煙囪。
- 大型輸送帶。
- 簡化的煤塊色塊。

### 動畫

- 輸送帶緩慢運作。
- 工業轉輪運轉。
- 小煤塊以固定節奏移動。

如果要呈現煙霧，只能是藝術性的工廠意象，不能暗示它代表即時排放量。

### NPC

一位有小鬍子的老工程師。

可能的台詞：

「老機器也是很可靠的！」

「讓我看看今天的工作量……」

「這個時代變化真快呀。」

避免把任何能源類型簡化成絕對的好人或壞人。

---

## 03. 太陽能發電廠

暫定性格：陽光、活潑、有點愛睡覺。

### 美術

- 幾塊大色塊太陽能板。
- 大大的太陽。
- 簡潔的地面與花草。
- 一座可愛的小控制室。

### 動畫

- 太陽緩慢移動。
- 面板可以有微小的圖案變化。
- 發電功率提高時，設備變得更活躍。
- 夜間發電功率歸零時進入休息狀態。

不要直接使用台電的全台太陽能發電功率推測特定地點的實際雲量或日照。

### NPC

一位活力十足的太陽能小員工。

白天：

「太陽出來啦！開工開工！」

晚上：

「我今天下班了，明天見！」

陰天且有可靠資料依據時：

「今天的陽光好像有點害羞。」

NPC 必須根據真實數據狀態選擇台詞，不能隨機說出與資料矛盾的內容。

---

## 04. 風力發電廠

暫定性格：自由、慢悠悠、看心情工作。

### 美術

- 幾座巨大但圓潤的風車。
- 柔和的丘陵。
- 簡潔的草地。
- 小小的維修站。

### 動畫

- 風車持續旋轉。
- 以實際發電功率改變整體活躍度。
- 輕微的草地擺動。
- 不同風車的旋轉速度可以略有差異。

重要：

**發電功率不是直接測量的風速。**

動畫只能作為發電活躍程度的藝術性表現。

不能把風車轉速標示成真實風速。

### NPC

一位喜歡吹風的小角色。

台詞：

「今天風很賞臉呢！」

「風去哪裡了……」

「轉呀轉呀轉～」

「今天先慢慢來。」

## 05. 水力發電廠

暫定性格：溫柔、安靜、可靠。

### 美術

- 一道幾何造型的小水壩。
- 大面積藍綠色水流。
- 小型渦輪。
- 簡潔的河道。

### 動畫

- 水流緩慢前進。
- 發電功率提高時，水流視覺節奏可稍快。
- 水面有極簡波紋。
- 渦輪輕輕旋轉。

重要：

實際發電功率不等於水庫水位、水流量或水壩放水量。

這些動畫只是用來象徵電力產出。

### NPC

一位非常悠閒的小水滴工程師。

台詞：

「慢慢流，也可以很努力。」

「今天的工作很順利。」

「水流的節奏真舒服呀。」

## 06. 其他能源工坊

暫定性格：神祕、博學、充滿奇怪的小發明。

這一格代表其餘經過正確分類的能源項目。

### 美術

可以設計成：

**一座專門收集不同能源的小小實驗工坊。**

有：

- 幾個不同的能源容器。
- 簡單的小型機械。
- 色塊輸送管線。
- 小燈泡。
- 精簡的儀表。

但不要讓它變成一個科技感控制台。

### 動畫

依實際資料：

- 不同能源來源的小裝置運作。
- 小型機械轉動。
- 儀表的色塊變化。
- 如果沒有可用發電功率，呈現休息或等待狀態。

### NPC

一位古怪的小發明家。

台詞：

「除了那五位，我這裡還有不少幫手！」

「能源的世界可是很複雜的。」

「今天來看看誰在工作吧！」

### 資料分類注意

請先確認官方資料中的：

- 燃氣
- 燃煤
- 太陽能
- 風力
- 慣常水力
- 燃油
- 汽電共生
- 抽蓄水力
- 儲能
- 其他再生能源
- 核能（若資料有）

等欄位的實際分類與意義。

六個虛擬類別必須互斥、可追溯，不得重複計算。

尤其抽蓄可能涉及抽水耗電與發電兩種狀態，不能把負值當成普通正發電功率。

核能如果目前沒有發電，不能為了湊角色而假裝仍在發電。

# 04｜真實資料來源

## 主要資料 A：各機組發電量

台電官方開放資料：

https://data.gov.tw/dataset/8931

可能的直接 JSON 資源：

https://service.taipower.com.tw/data/opendata/apply/file/d006001/001.json

官方資料包含：

- 機組類型
- 機組名稱
- 裝置容量（MW）
- 淨發電量（MW）
- 淨發電量／裝置容量比（%）
- 備註

官方標示每 10 分鐘更新。

請實際呼叫資料端點、確認格式與內容。

不要只根據欄位名稱假設資料結構。

## 主要資料 B：今日電力供需

https://data.gov.tw/dataset/162595

可能的直接 JSON 資源：

https://service.taipower.com.tw/data/opendata/apply/file/d006020/001.json

重要欄位：

- `curr_load`
- `curr_util_rate`
- `fore_peak_resv_rate`
- `fore_peak_resv_indicator`
- `fore_peak_hour_range`
- `publish_time`

請優先利用這個資料來源顯示：

- 台灣目前用電功率
- 官方供電使用率
- 今日預估尖峰備轉容量率
- 今日預估尖峰供電燈號

## 重要的資料概念

請嚴格區分：

### 功率

MW 或萬瓩。

代表某個時間點的發電／用電功率。

### 電量

MWh、kWh 或度。

代表一段時間累積的電能。

本網站首頁應以：

**現在台灣用了多少電？**

為生活化的提問。

但正式數據標籤應使用：

**目前用電功率（萬瓩）**

不要直接把 MW 當成今日累積用電度數。

如果未來要顯示當日累積用電量，必須使用適當的累積資料或明確的時間積分方法，不能把瞬間功率直接當成每日電量。

另外，不要強迫各能源別發電量加總一定等於系統目前用電量。

兩者可能因資料時間、統計範圍、系統運作與其他因素而不同。

# 05｜發電廠如何根據資料動起來

請建立獨立的：

`PowerData → AnimationState`

映射系統。

這個系統是作品的核心。

## 5.1 基本原則

每座發電廠的動畫都要與真實數據產生關係。

但不能粗暴地讓：

「發電量越大，動畫就越快。」

因為不同能源的容量與運作方式完全不同。

請將動畫分成三層：

### Layer A｜基礎環境動畫

不論資料如何，都可以存在的療癒微動態。

例如：

- 水面波紋
- 太陽微微移動
- NPC 呼吸
- 葉子輕輕擺動

### Layer B｜資料驅動動畫

根據發電狀態變化。

例如：

- 風車運作活躍程度
- 渦輪動畫節奏
- 工廠輸送帶速度
- 太陽能板的活動指示

### Layer C｜事件動畫

在有明確數據事件時觸發。

例如：

- 某能源占比明顯增加。
- 某能源發電功率快速下降。
- 官方供電燈號改變。
- 台灣目前用電功率達到今天新的觀測高點。

事件必須根據實際可用的資料比較產生。

若缺少歷史資料，不得捏造今天的最高紀錄。

## 5.2 動態變化

資料更新時不要立即跳轉。

例如：

風力發電由 500 MW 變為 800 MW。

風車動畫應該緩慢過渡，而非突然加速。

所有數值變化應盡量保持柔和。

## 5.3 長時間觀賞

這個網站可能持續開著幾小時。

請避免：

- 大幅度閃爍
- 短週期重複動畫
- 大量飄散粒子
- 過度頻繁的角色對話
- 瘋狂旋轉的設備
- 無休止的畫面切換

**我希望六間發電廠的運作看起來像有生命，而不是六個不停播放的 GIF。**

# 06｜NPC 角色與台詞系統

這是本網站非常重要的特色。

每座發電廠都有自己的角色。

角色應該很可愛，但不需要複雜的人物插畫。

可以使用：

- 小小的工程師
- 擬人化機械
- 幾何形狀角色
- 小水滴
- 可愛的發電廠吉祥物

### 角色造型原則

- 極簡色塊。
- 好辨識的輪廓。
- 少量表情。
- 不需要大量細節。
- 能以少數 SVG 元件製作不同表情。

## 6.1 台詞類型

至少包含：

### 日常台詞

與角色個性相關。

### 資料台詞

根據目前的發電量、占比或狀態發言。

### 事件台詞

當某項數據顯著變化時觸發。

### 跨廠互動台詞

角色偶爾互相對話。

例如：

太陽能員工：

「我今天超有精神！」

風力員工：

「真好……我這邊還在等風。」

這類對話必須符合當時的資料狀態。

## 6.2 NPC 台詞規則

不要讓所有 NPC 同時說話。

請建立全域的台詞排程器：

- 同時最多一個主要對話事件。
- 一般對話間隔應足夠長。
- 重要事件可適度優先。
- 每句話應能舒適閱讀。
- 避免短時間重複相同台詞。
- 沒有台詞時，角色仍有自己的待機動態。

台詞應該像偶爾從工作中的小世界冒出的驚喜。

不是不斷彈出的通知。

## 6.3 節電提醒

希望 NPC 偶爾能說一些節約能源的話。

例如：

「冷氣設定高一點點，也能省一些電喔！」

「沒用到的燈記得關掉！」

「出門前，看看有沒有忘記關的電器！」

但請注意：

**供電充裕時不要假裝台灣即將缺電。**

如果官方供電燈號正常，就可以用溫柔的日常節電提醒。

只有官方資料真的呈現供電吃緊時，才使用更明確的相關台詞。

不得透過自製推測擅自發布缺電、停電或電網危機警告。

## 6.4 NPC 語氣

我希望他們：

- 可愛
- 有個性
- 有點荒謬幽默
- 不說教
- 不過度幼稚
- 有工作日常感

我特別喜歡那種：

**一群小小角色，正在很認真地做一件很大的事情。**

這也是整個作品的情感核心。

# 07｜整體供電狀態

六座發電廠是主視覺，但網站仍應清楚回答：

**現在台灣用了多少電？**

請設計一個簡潔的整體資訊區。

至少包含：

- 目前用電功率
- 供電使用率
- 官方預估尖峰備轉容量率
- 官方供電燈號
- 資料更新時間

注意：

**目前用電功率、供電使用率與預估尖峰備轉容量率並非同一種指標。**

請不要混為一談。

## 7.1 資訊呈現方式

不要設計成一般 Dashboard 的四個大 KPI 卡片。

可以考慮：

- 像印刷海報的數字標籤。
- 小型紙張資訊欄。
- 一塊由色塊構成的全台供電狀態牌。
- 自然整合在六宮格上方。

希望像一幅插畫作品的資訊標題。

不要做成企業管理後台。

## 7.2 官方燈號

以台電發布的原始狀態為依據。

可以顯示：

- 供電充裕
- 供電吃緊
- 其他官方狀態

但不得自行重新定義官方燈號。

請清楚區分即時用電數據與「預估今日尖峰」的官方燈號。

---

# 08｜六宮格的互動

使用者可以點擊任一發電廠。

進入該發電廠的詳細觀察模式。

## 8.1 詳細模式

放大該座發電廠的插畫。

提供：

- 能源名稱。
- 目前發電功率。
- 占總發電功率比例。
- 目前可用的相關機組資訊。
- 最近變化（需有可靠歷史快照）。
- 能源簡介。
- NPC 對話。

詳細畫面仍然以插畫為主。

不要突然變成資訊量爆炸的報表。

## 8.2 返回六宮格

返回時要有漂亮、自然的動畫。

例如：

放大的場景縮回原本的位置。

但請避免複雜、不穩定的動畫架構。

## 8.3 觀賞與探索

我希望這個網站同時支援：

### 觀賞者

什麼都不按，只看六座發電廠運作。

### 探索者

點擊角色、發電廠，了解更多數據。

這兩種使用方式都應該是完整的體驗。

---

# 09｜歷史數據與事件偵測

如果要呈現：

- 今天誰最努力
- 某能源發電增加最多
- 今日新高
- 近一小時變化
- 發電占比排名

就必須有對應的資料。

第一版請建立資料快照架構。

但不要要求使用者一定要有資料庫才能看到網站。

可採取：

- 伺服器快取。
- 週期性資料儲存。
- 前端當次工作階段快照。
- 可選的持久化儲存。

請根據現有專案選擇最合適的方案。

如果當次工作階段只有兩筆資料，不能宣稱取得了完整的 24 小時趨勢。

## 可研究的歷史來源

https://data.gov.tw/dataset/37331

這是台電各機組過去發電量資料。

但此資料集按月發布，且有發布延遲，不可當作最近十分鐘的資料來源。

歷史圖表需要顯示實際資料涵蓋時間。

# 10｜六種場景狀態

請至少建立：

1. 正常運作。
2. 高發電活躍度。
3. 低發電活躍度。
4. 未發電／待命。
5. 資料載入中。
6. 資料過期或不可用。

注意：

「未發電」不代表機組故障。

可能是：

- 夜間沒有太陽能。
- 依調度未發電。
- 機組檢修。
- 其他原因。

不能未經驗證就顯示 NPC 說：

「糟糕！我壞掉了！」

資料缺失也不等於發電量為零。

請嚴格區分這些狀態。

---

# 11｜響應式設計

## Desktop

3 × 2 六宮格。

盡可能在一個視窗內完整觀看六座發電廠。

如果螢幕尺寸不足，允許適當捲動，不得為了硬塞畫面而犧牲可讀性。

## Tablet

可以調整為 2 × 3。

## Mobile

優先評估：

- 2 × 3 緊湊六宮格。
- 單座發電廠放大檢視。
- 適合手機的垂直觀賞模式。

重要：

手機版不能只是把桌面六宮格縮小。

每座發電廠的場景應具有響應式構圖能力。

NPC 台詞也要避免遮住主要建築和數據。

---

# 12｜動畫效能

由於網站可能長時間開啟，請特別重視：

- SVG 動畫效能。
- CSS Transform。
- requestAnimationFrame 使用方式。
- Page Visibility API。
- 動畫清理。
- 資料快取。
- API 呼叫頻率。
- 記憶體管理。
- Reduced Motion。

不要為了簡單動畫引入大型 3D 引擎。

優先採用 SVG + CSS + 少量 JavaScript。

如果使用 React，避免高頻動畫造成整個六宮格重新渲染。

---

# 13｜無障礙

至少包含：

- 語意化 HTML。
- 正確的按鈕。
- 鍵盤操作。
- Focus Visible。
- 足夠的文字對比。
- 不只依顏色顯示供電狀態。
- `prefers-reduced-motion`。
- 重要數據的文字替代資訊。
- 適當的更新公告機制。

動畫與 NPC 不應影響資料閱讀。

---

# 14｜資料串接與錯誤處理

請實際驗證官方資料端點。

包含：

- HTTP 狀態。
- JSON 格式。
- 欄位型別。
- 更新時間。
- CORS。
- 可能的快取。
- 負值。
- 零值。
- 缺失值。
- 機組類別變化。

建議採用小型後端代理或 Serverless Function，以集中處理資料解析、快取和錯誤狀態。

但不要為簡單作品建立不必要的大型後端。

## Demo Mode

請建立完整的展示模式。

至少包含：

- 白天太陽能活躍。
- 夜間太陽能休息。
- 風力發電較高。
- 風力發電較低。
- 官方供電燈號切換的模擬事件。
- API 失敗。

展示資料必須明確標示為 Demo。

不能偽裝成台電即時資料。

# 15｜開發階段

請直接執行，不需要每一階段都停下來詢問。

## PHASE 1：資料研究

先驗證台電官方資料。

確認：

- 真實端點。
- 回傳資料。
- 六種能源分類。
- 功率單位。
- 日期時間。
- 發電與用電的差異。
- 供電燈號語意。

建立資料分類與單位轉換測試。

## PHASE 2：美術原型

這是第一個重要的品質關卡。

請先製作六座發電廠的靜態 SVG 場景。

不要急著串接 UI 或動畫。

必須先達到：

**即使六座發電廠完全不動，也是一幅漂亮、有創意、有辨識度的絹印風插畫。**

請特別檢查：

- 六座建築是否太相似。
- 配色是否具有變化。
- 色塊是否足夠簡潔。
- 構圖是否協調。
- NPC 是否可愛。
- 是否過度裝飾。
- 是否符合我現有作品的美學。

## PHASE 3：動畫

為六座發電廠建立不同的運作動畫。

不要使用同一種動畫套在所有場景上。

每個發電廠應該有自己獨特的運動語言。

## PHASE 4：即時資料串接

完成：

- 台電資料取得。
- 資料正規化。
- 能源分類。
- 六宮格功率與占比。
- 整體用電。
- 供電燈號。
- 更新時間。

## PHASE 5：資料驅動動畫

將發電數據映射為動畫狀態。

加入平滑過渡與合理限制。

## PHASE 6：NPC 系統

建立：

- NPC 角色。
- 表情。
- 台詞庫。
- 狀態判斷。
- 對話排程。
- 事件觸發。
- 防重複機制。

## PHASE 7：互動與響應式

完成：

- 單座發電廠詳細模式。
- 六宮格返回。
- 全屏觀賞模式。
- Mobile。
- Tablet。
- 無障礙。

## PHASE 8：美術精修

這是不可省略的階段。

請實際在瀏覽器檢查：

- 六宮格整體構圖。
- 每個場景的細節。
- Desktop。
- Mobile。
- 動畫節奏。
- 色彩協調。
- NPC 對話是否自然。
- 數據資訊是否干擾插畫。

如果可以，請截取實際執行畫面檢查。

不要只根據程式碼推測美術效果。

# 16｜完成標準

最後的網站應符合：

### 美術

- 六座發電廠有獨立的視覺個性。
- 延續極簡可愛絹印色塊風。
- 色相和彩度有豐富但合理的變化。
- 不像一般電力 Dashboard。
- 不像科技產品展示頁。
- 靜態畫面本身就有觀賞價值。

### 動態

- 每座發電廠有獨特動畫。
- 動畫與實際數據有合理關係。
- 變化平滑。
- 長時間觀看不疲勞。

### NPC

- 每座發電廠都有可愛的角色。
- 台詞有個性。
- 偶爾出現幽默互動。
- 能根據數據觸發事件。
- 不傳達錯誤的電力資訊。

### 資料

- 正確串接台電官方資料。
- 清楚標示更新時間。
- 不混淆功率與累積電量。
- 不重複計算能源別。
- 不偽造即時資訊。
- API 失敗時有妥善處理。

### 體驗

- 一眼能看到六座發電廠。
- 容易理解目前電力供需。
- 可觀賞，也可探索。
- 手機版完整。
- 可長時間開啟。

# 18｜最終創作理念

請記住：

**這不是一個放了六張插畫的電力資訊網站。**

**這是一個由真實電力資料驅動、六座小小發電廠正在努力工作的世界。**

使用者打開畫面。

左上角的燃氣廠正在忙碌。

旁邊的風力廠慢慢轉動。

太陽能廠的小員工正在曬太陽。

水力廠的河水緩緩流過。

偶爾一位 NPC 冒出一句：

「今天大家都很努力呢！」

然後，使用者會發現：

這些小小的動畫，其實反映的是台灣真正正在發生的電力活動。

我希望這是一個：

**有真實數據、有可愛角色、有細膩動畫、有美學高度，也有一點荒謬幽默的作品。**

而且即使使用者完全不操作，也願意一直開著它。

請以美術品質為第一優先，資料準確性為不可妥協的底線，直接開始執行。
