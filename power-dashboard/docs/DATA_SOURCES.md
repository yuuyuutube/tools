## 端點

| 用途 | 資料集 | 端點 | 更新 |
| --- | --- | --- | --- |
| 各機組淨發電量 | [data.gov.tw/dataset/8931](https://data.gov.tw/dataset/8931) | `https://service.taipower.com.tw/data/opendata/apply/file/d006001/001.json` | 官方標示每 10 分鐘 |
| 今日電力資訊 | [data.gov.tw/dataset/162595](https://data.gov.tw/dataset/162595) | `https://service.taipower.com.tw/data/opendata/apply/file/d006020/001.json` | 約每 10 分鐘 |

實測：

- 兩個端點都是 HTTP 200、`application/json`、IIS 靜態檔，有 `Last-Modified`／`ETag`。
- **沒有 `Access-Control-Allow-Origin`**，瀏覽器不能直接讀。所以本機用 `server/` 代理；GitHub Pages 讀 Actions 每 10 分鐘抓一次、推到 `weather-data` 分支的 `power-dashboard.json`。
- 發電檔開頭有 UTF-8 BOM，`JSON.parse` 前要去掉。
- 不需要金鑰。

## 各機組發電量（d006001）

```json
{ "DateTime": "2026-11-16T15:10:00",
  "aaData": [ { "機組類型": "燃氣", "機組名稱": "大潭CC#1", "裝置容量(MW)": "742.7",
               "淨發電量(MW)": "677.3", "淨發電量/裝置容量比(%)": "91.194%", "備註": " " }, … ] }
```

- `DateTime` 是**臺灣時間、沒有時區**，解析時補 `+08:00`。
- 所有數值都是字串。缺值有 `"-"`、`"N/A"`，一律當 `null`（**缺值不是 0**）。
- 每個類型最後有一列 `機組名稱: "小計"`，裝置容量欄是 `"17216.3(28.044%)"` 這種格式。**小計列不加總**，只拿來交叉比對（`classify().check`，不一致時快照標 `subtotal-mismatch`）。
- 部分機組裝置容量是 `"-"`（例如新機組、註 10），它們的發電量照算，但不進容量因數。
- 類型名稱可能夾 HTML：`"儲能負載(Energy Storage System Load)</b>"`。先去標籤與英文括號。
- 「儲能負載」列是抽蓄抽水／電池充電，值為 0 或負數。

### 六座發電廠的分類（互斥、可追溯）

| 虛擬發電廠 | 官方「機組類型」 |
| --- | --- |
| 燃氣 | 燃氣、民營電廠-燃氣 |
| 燃煤 | 燃煤、民營電廠-燃煤 |
| 太陽能 | 太陽能 |
| 風力 | 風力 |
| 水力 | 水力（慣常水力，含小水力） |
| 其他（工坊） | 儲能（抽蓄水力發電＋電池放電）、汽電共生、燃料油、其它再生能源（地熱、生質能）、核能（若出現） |
| 不算發電 | 儲能負載（抽水、充電），以及任何類別中的負值 |

- 每一列機組只會落在一類；官方小計列不計入。2026-11-16 15:10 的檔案六類合計 32,974.1 MW，各類與官方小計完全一致（測試 `tests/data.test.js`）。
- 未見過的類型先依關鍵字歸類（含「燃氣」→燃氣…），歸不進去的放進工坊並列在 `unclassified`，說明頁會顯示。
- 這份檔案沒有核能機組（核二 Gas、核三 Gas 是燃料油類的氣渦輪），因此工坊不會出現核能罐。
- 汽電共生的實際燃料混合（多為煤、氣），官方另列一類，本站照官方放在工坊，不拆給燃煤或燃氣。

### 占比

占比 = 該類淨發電 ÷ 六類淨發電合計。**分母不是目前用電功率**：兩份資料的時間、統計範圍不同，加總本來就不必相等（實測 32,974 MW 對 3,295 萬瓩）。

## 今日電力資訊（d006020）

```json
{ "records": [ { "curr_load": "3295.0", "curr_util_rate": "82" },
               { "fore_maxi_sply_capacity": "4231.4", "fore_peak_dema_load": "3380.0", "fore_peak_resv_capacity": "851.4",
                 "fore_peak_resv_rate": "25.19", "fore_peak_resv_indicator": "G", "fore_peak_hour_range": "13:00-15:00",
                 "publish_time": "115.11.16(一)15:10" },
               { "yday_date": "115.11.15", … }, { "real_hr_maxi_sply_capacity": "3994.9", … } ] }
```

- 單位是**萬瓩**（1 萬瓩 = 10 MW）。
- `publish_time` 是民國年＋星期，轉成 ISO。
- 四筆 record 合併成一個物件再讀。

### 三種指標，不混在一起

| 畫面 | 欄位 | 意義 |
| --- | --- | --- |
| 大數字 | `curr_load` | **目前用電功率**（某一時刻的功率），不是今天累積的度數 |
| 使用率 | `curr_util_rate` | 台電公布的目前供電使用率 |
| 燈號＋尖峰備轉 | `fore_peak_resv_rate`、`fore_peak_resv_indicator`、`fore_peak_hour_range` | **今日預估尖峰**的備轉容量率與官方燈號，不是此刻 |

燈號只照官方字母顯示：`G` 供電充裕、`Y` 供電吃緊、`O` 供電警戒、`R` 限電警戒、`B` 限電準備。不認識的字母原樣顯示「燈號 X」，不自行解讀，也不用本站的推算改寫燈號。

## 歷史與事件

- 只保存真的收到過的資料點（發電時間為鍵），保留 26 小時：本機在 `.power-cache/history.json`，Pages 在快照的 `history`。
- 詳細頁的「最近變化」標出實際涵蓋時間與筆數；少於兩筆就顯示「資料累積中」。
- 事件只用至少兩筆真實資料比較：一小時內占比 +3 個百分點、相鄰兩筆下降 ≥ 25% 且 ≥ 80 MW、燈號改變、太陽能歸零／恢復。
- 「今日用電新高」只有在今天 00:20 起的觀測連續（相鄰間隔 ≤ 25 分）時才成立；否則不說。
- 月報性質的 [各機組過去發電量（37331）](https://data.gov.tw/dataset/37331) 有發布延遲，不能當近十分鐘資料，本版未使用。

## 新鮮度與失敗

| 情況 | 畫面 |
| --- | --- |
| 資料時間 ≤ 30 分 | 正常 |
| 30 分 – 3 小時 | 時間標橘色、紙籤變淡、NPC 只說「等新數字」 |
| > 3 小時 | 同上，動畫放慢到休息節奏 |
| 單一端點失敗 | 另一半照常；伺服器沿用 6 小時內的快取並標示 |
| 全部失敗、從沒成功過 | 數值顯示「—」、紙籤標「資料缺」，5 分鐘後自動重試 |
| 沒有資料來源（純靜態主機） | 自動進入展示資料，標「展示資料（未連上資料來源）」 |

## 限制

- 台電檔案偶爾晚幾分鐘；GitHub Actions 排程也可能延遲，Pages 上的資料可能比官方晚 10–20 分鐘。
- 展示資料的機組名稱是虛構的「示範機組」。
- 本站不計算累積用電度數。
