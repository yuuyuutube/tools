# Claude Code 開發任務｜耳朵年齡機

## 0. 任務簡介

請製作一個完整、可直接使用的互動網站：

**《耳朵年齡機》**

這是一個可愛、極簡、帶有一點幽默感的聲音互動實驗。

使用者按下「開始」後，網站播放從低頻逐漸升高到高頻的聲音。當使用者發現自己已經聽不到聲音，就按下白旗按鈕投降。

接著使用者可以重新播放、拖曳頻率刻度、用左右方向鍵細修，確認自己真正聽不到的頻率。

最後網站顯示趣味估算的「耳朵年齡」，並產生一張極簡、可儲存與分享的結果海報。

**這不是醫療檢測工具，而是一件可愛、有趣、能讓朋友互相比較的互動網頁作品。**

請直接實作，不要只產出設計稿、概念文件或待辦清單。

---

# 1. 整體美術方向

## 核心風格

**極簡可愛派（Minimal Cute）**

參考方向：

- 簡潔、富有性格的動物插畫
- 柔和但不沉悶的配色
- 大量留白
- 精緻的排版
- 少量、恰到好處的動畫
- 有一點藝術玩具、獨立設計網站的氣質

不要做成：

- 一般兒童科普教材網站
- 傳統線上問卷
- 醫院聽力檢測介面
- 科技儀表板
- 大量卡片堆疊的 SaaS 網站
- 五顏六色、到處都是可愛裝飾的介面

希望畫面非常克制。

**每個畫面都應該有一個明確的視覺主角。**

## 配色

請自主設計一套成熟、有設計感的柔和配色。

建議：

- 暖白色或奶油色背景
- 深灰、深棕或柔和墨色文字
- 一至兩個主要強調色
- 動物可有各自的顏色，但需維持統一的整體視覺系統

不需要大量漸層、玻璃擬態或重陰影。

## 動物美術

動物應採用統一的原創極簡插畫風格：

- 簡化輪廓
- 大色塊
- 極少細節
- 可以有簡單的小眼睛或表情
- 不依賴大量線條
- 即使縮小也能辨識
- 帶有一點幽默和個性

請優先使用 SVG 製作原創動物插畫，以確保清晰度、響應式縮放與動畫能力。

不要直接使用 emoji 取代正式插畫。

# 2. 動物頻率譜

## 核心概念

隨著聲音頻率升高，畫面中的動物也會逐漸更換。

從低沉、巨大、厚重的動物意象，逐步轉變成輕盈、細小、高頻的動物意象。

建議動物順序：

1. 鯨魚
2. 大象
3. 熊
4. 貓
5. 小鳥
6. 蜜蜂
7. 蚊子

這些動物主要是**頻率高低的視覺比喻**，不是其實際發聲頻率的科學分類。

不要暗示「這隻動物的叫聲就是目前播放的 Hz」。

## 動物切換方式

希望切換自然、可愛，但保持極簡。

可以使用：

- 淡入淡出
- 微小的位移
- 輕微的縮放
- 小幅度漂浮
- 依角色特性安排極少量的動作

例如：

鯨魚輕輕擺尾巴、大象稍微動耳朵、熊眨眼、貓動一下耳朵、小鳥跳一下、蜜蜂輕微漂浮、蚊子抖動翅膀。

不需要複雜骨架動畫。

請確保角色始終在畫面視覺中心，不因不同動物的比例造成畫面劇烈跳動。

## 頻率與動物關係

使用統一的對數頻率進度，將測試範圍映射為 0–100%。

再依進度切分動物出現的區段。

請將動物、頻率區間及切換設定集中管理，方便未來調整。

# 3. 網站流程

網站由四個主要狀態構成：

1. 首頁
2. 聲音測試
3. 頻率細修
4. 結果海報

不需要四個不同的 URL。

可以使用單頁式狀態切換完成，搭配簡潔而平順的轉場。

# 4. 首頁

## 畫面內容

主要標題：

**耳朵年齡機**

副標：

**你的耳朵，能撐到幾 Hz？**

畫面中央可以是一隻可愛的小動物，或讓幾隻動物形成極簡排列。

主要按鈕：

**開始測試**

輔助提醒：

- 建議使用耳機，在安靜環境進行
- 請使用舒適、偏低的音量，不要為了聽見而加大音量
- 本測試僅供趣味參考

請讓這些說明融入排版，不要使用大面積警告視窗。

## 開始前的音量確認

由於使用者設備的音量可能不同，正式測試前需要一個非常簡單的準備步驟。

請使用安全、舒適的中頻測試音，讓使用者確認：

「我聽得到，而且音量很舒服。」

確認後才能開始掃頻。

不要自動調高系統音量，也不要要求使用者把音量開到最大。

---

# 5. 聲音測試

## 操作

使用者點擊開始後，播放連續、平滑、逐漸升高的純音。

建議：

- 起始頻率：500 Hz
- 終點頻率：18,000 Hz
- 掃頻方式：對數式
- 預設測試時間：約 35 秒

請將這些數值集中管理，方便調整。

畫面顯示目前頻率，例如：

**8,420 Hz**

搭配一條非常細的進度刻度。

不要設計複雜的儀表板。

## 音效技術

使用 Web Audio API。

要求：

- 聲音必須由明確的使用者操作啟動
- 使用 OscillatorNode 產生純正弦波
- 透過 GainNode 控制輸出
- 避免開始、停止或切換頻率時的爆音
- 停止播放時使用短暫淡出
- 不要使用突然跳變的頻率
- 不要使用會造成音量突增的音效
- 預設採用保守的低輸出增益
- 不要因使用者聽不到高頻而自動增加音量

注意 Web Audio 的取樣率、Nyquist 頻率及硬體實際播放能力。

如果設備不支援指定頻率或無法可靠輸出，不可以假裝測量準確。

另外，從低頻持續上升時，使用者可能因為音量感知差異而誤以為聽不到。因此這只能是趣味測試，不能宣稱其結果具有臨床效度。

## 主要互動

畫面最醒目的操作是：

**🏳 我聽不到了**

白旗是整個網站的核心識別。

請盡可能使用自己設計的簡單白旗 SVG 圖示，而不是完全依賴 emoji。

按鈕要有：

- 足夠大的點擊範圍
- 清楚的 hover / focus 狀態
- 細緻的按下回饋
- 手機上容易點擊

當使用者按下白旗：

1. 記錄當下頻率
2. 立即平滑停止聲音
3. 停止計時及掃頻
4. 進入頻率細修畫面

## 暫停及重新開始

請提供不搶走白旗視覺重點的暫停功能。

如果測試被打斷，允許重新開始。

切換分頁或網頁進入背景時，應停止或暫停聲音，避免使用者失去控制。

掃頻到達最高值時，不可無限持續播放。

如果使用者一路到 18,000 Hz 都沒有投降，應提供「我一路聽到了終點」的選項，並將結果標示為測試上限，而不是假裝找到真正的聽力極限。

# 6. 頻率細修畫面

這是非常重要的一個階段。

使用者按下白旗時，不要立刻顯示年齡。

先讓使用者確認真正的聽覺邊界。

## 畫面

主標題：

**你是在這裡投降的嗎？**

中央顯示：

**14,280 Hz**

下方：

- 可拖曳的頻率刻度
- 向左微調按鈕
- 向右微調按鈕
- 重播目前頻率
- 確認結果

## 微調方式

支援：

- 滑桿拖曳
- 左右箭頭按鈕
- 鍵盤左右方向鍵
- 手機觸控

建議微調：

- 一般每次 100 Hz
- 需要時可使用 25 Hz 精細微調

不需要讓整個介面變得像專業聲學儀器。

## 更可靠的確認方式

使用者應該能方便地比較：

- 最後還聽得見的頻率
- 第一個聽不到的頻率

可以設計非常簡單的 A / B 比較互動。

例如：

「這裡還聽得到」

「這裡聽不到了」

並允許使用者重複確認。

請避免只依賴連續掃頻的第一次反應，因為人類的反應時間會影響停止位置。

**特別注意：音量必須維持相同設定，不可以為了讓高頻更容易被聽見而提高增益。**

## 重播行為

重播音效必須由使用者主動操作。

每次播放採用短暫、固定時長、帶有淡入淡出的音訊。

避免使用者拖曳滑桿時，持續產生不可控的聲音。

請提供停止播放的方式。

## 確認

主要按鈕：

**確定，在這裡投降！**

確認後才進入結果畫面。

---

# 7. 趣味耳朵年齡計算

## 核心要求

這是娛樂性測驗，不是醫療診斷。

網站應將最高可聽頻率轉換為趣味年齡分組。

不要宣稱能透過一個頻率準確判斷使用者的實際生理年齡。

也不要使用沒有可靠來源的年齡對照表，卻把它包裝成醫學標準。

## 建議設計

使用一套獨立設定的趣味年齡分級資料。

請：

1. 調查可用的可靠參考資料。
2. 區分研究資料與網路流傳的趣味對照表。
3. 在沒有足夠證據建立精確歲數公式時，使用寬鬆的年齡區間或稱號。
4. 若要顯示單一數字，必須清楚標註為趣味換算，不能表現為精確測量結果。
5. 不要假裝不存在的科學精準度。
6. 將對照規則放在獨立的設定檔，方便日後更換。

例如結果可以是：

**耳朵年齡：大約 30 多歲**

或適合分享的趣味稱號。

請自行提出一套幽默、可愛、與動物世界觀一致的分級文案。

如果使用者到達設備或測試上限，不能將該頻率視為其真正聽力極限。

---

# 8. 結果畫面

## 設計方向

結果頁應該像一張簡潔、可收藏的小海報。

不要做成傳統數據報表。

請把結果本身設計成具有完成度的視覺作品。

## 主要資訊

包含：

- 網站名稱：耳朵年齡機
- 趣味估算的耳朵年齡
- 最高確認可聽頻率或測試邊界
- 一句簡短幽默文案
- 一隻與結果相呼應的動物插畫
- 小小的趣味測驗註記

例如：

耳朵年齡機

**大約 30 多歲**

你守到了 14,800 Hz

「蚊子還沒完全贏過你。」

搭配一隻小蚊子或拿著白旗的動物。

## 結果文案

請準備多組可愛、幽默、簡短的文案。

文字不要太多。

方向例如：

- 「蚊子還沒完全贏過你。」
- 「你的耳朵決定下班了。」
- 「高頻世界向你揮手告別。」
- 「這一局，蚊子勝。」
- 「你比想像中更能撐。」
- 「耳朵已經舉白旗了。」

不要有羞辱年紀或嘲笑聽力障礙的文案。

角色的反應可以幽默，但不要把聽力差異塑造成缺陷。

# 9. 海報分享功能

## 核心要求

使用者應可以將結果儲存成圖片，或透過裝置原生分享功能分享。

分享圖必須是**真正產出的圖片**，不能只截圖目前畫面的某一塊。

## 視覺

非常簡潔，像一張設計精緻的小海報。

建議：

- 直式
- 大量留白
- 清楚的文字層級
- 一隻原創動物插畫
- 一個大大的耳朵年齡結果
- 一個較小的 Hz 數字
- 一句幽默評語
- 極小的網站名稱或網址

請確保：

- 不包含操作按鈕
- 不包含滑桿
- 不包含網頁導覽
- 不包含測試說明長文
- 不包含多餘裝飾

請設計成即使單獨出現在朋友的社群動態中，也會令人想知道這是什麼測驗的視覺作品。

## 下載規格

建議輸出：

1080 × 1350 px

PNG 格式。

請確保圖片尺寸固定，不依賴使用者螢幕解析度。

## 技術要求

可以使用 Canvas、SVG 或適合的前端圖片輸出方式。

必須處理：

- 字體渲染
- 中文字型
- SVG 插畫
- 高解析度輸出
- 手機瀏覽器
- 圖片載入或繪製完成後才匯出

優先使用原生 Web Share API 分享圖片。

如果瀏覽器不支援圖片分享，應提供 PNG 下載作為替代。

不要讓使用者按下分享後得到空白圖片。

# 10. 響應式設計

這個網站應該在手機和桌面上都非常好看。

## 手機

以直式單欄為主。

- 動物維持視覺中心
- 白旗按鈕大而容易點擊
- 數字清楚
- 滑桿容易觸控
- 重要功能不用捲動太久

## 桌面

不要單純把手機介面放大。

應保留大量留白，讓整體看起來像獨立互動藝術網站。

避免內容過度分散到左右兩側。

使用適當的最大內容寬度。

---

# 11. 微互動與動畫

動畫原則：

**少量、有個性、有意義。**

例如：

- 動物輕輕呼吸或漂浮
- 耳朵、翅膀、尾巴有小動作
- 數字自然更新
- 白旗按下時微微晃動
- 動物切換時有輕柔的過渡
- 結果揭曉時有一個漂亮、克制的小動畫

避免：

- 大量粒子
- 長時間載入動畫
- 強烈畫面震動
- 到處亂飛的裝飾
- 需要等待動畫結束才能操作

支援 prefers-reduced-motion。

---

# 12. 無障礙與操作品質

請實作基本但完整的無障礙支援。

包括：

- 正確的語意化 HTML
- 所有按鈕皆可使用鍵盤操作
- 清楚的 focus 樣式
- 滑桿有正確標籤與目前數值
- 動物插畫若為裝飾用途，避免產生不必要的螢幕閱讀器資訊
- 不依賴顏色作為唯一狀態提示
- 適當的文字對比
- 不要讓每一次頻率更新都被螢幕閱讀器反覆朗讀

測試高度依賴聲音，應清楚說明無法取代專業聽力檢查。

# 14. 品質驗收

完成後，請自行檢查以下情境。

## 測試流程

- 首頁可以開始
- 音量確認正常
- 聲音從低頻順暢上升
- 頻率數字更新正確
- 動物依進度切換
- 按下白旗後聲音停止
- 可以細修頻率
- 左右方向鍵可以操作
- 可以重新播放測試音
- 可以確認結果
- 可以重新測試

## 邊界情況

- 使用者拒絕或尚未啟動 AudioContext
- 使用者切換分頁
- 使用者中途暫停
- 使用者連續快速按按鈕
- 使用者拖曳頻率滑桿
- 使用者沒有按白旗而到達最高頻率
- 使用者在手機上重新測試
- 使用者的裝置無法輸出特定高頻
- 瀏覽器不支援原生圖片分享

## 分享圖

- 可匯出 PNG
- 圖片不為空白
- 中文不亂碼
- 動物插畫正常
- 文字沒有溢出
- 不同結果可以生成不同海報
- 手機與桌面匯出的內容一致

如果具備瀏覽器測試環境，請實際執行網站並檢查畫面，而不是只檢查程式碼。

# 15. 美術品質要求

這個專案最重要的是整體完成度。

我不希望它看起來像 AI 快速生成的普通 Demo。

請特別注意：

1. 動物插畫必須有統一且獨特的設計語言。
2. 字級、間距、留白及視覺重心要經過設計。
3. 不要使用大量通用卡片組件。
4. 不要為了填滿空間而增加多餘文字。
